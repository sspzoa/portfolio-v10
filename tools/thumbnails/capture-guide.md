# 실제 화면 확보와 검수

## 화면의 기준

실제 서비스 화면을 우선한다. 서비스가 종료되었거나 로그인할 수 없다면 원본 저장소의 당시 버전을 실행한다. 원본 UI를 비슷하게 다시 그린 화면은 사용하지 않는다. 바꿀 수 있는 것은 익명 데모 데이터와 외부 연동 응답이다. 위젯, 폰트, 여백, 아이콘, 문구, 상태 전환은 원본을 유지한다.

저장소의 현재 버전이 포트폴리오에 적은 활동 시점과 같다는 보장은 없다. 날짜에 맞는 커밋을 먼저 고른다. 디미페이는 2025년 변경으로 얼굴 인식 안내가 달라져 2024년 말 앱과 키오스크 커밋으로 다시 캡처했다. 글루드는 디자인 시안 PDF와 실제 앱 화면 PDF를 구분해 실제 구현과 비교했다.

## 준비와 캡처

1. 원본 저장소, 커밋과 서비스 화면 경로를 확인한다. Flutter는 `.metadata`, SDK 제약과 잠금 파일에서 당시 버전을 찾는다. 맞는 SDK를 임시 작업 폴더에 설치한다.
2. 별도 작업 폴더에서만 앱과 데이터를 실행한다. 공유 운영 DB, Redis, 스토리지에 연결하지 않는다. 인증과 외부 API만 로컬 응답이나 에뮬레이터로 대체한다.
3. 실제 이름, 연락처, 결제 정보와 키를 제거한 데모 데이터를 충분히 넣는다. 원래 코드에 없는 기능이나 성공 상태는 만들지 않는다.
4. 핵심 기능이 드러나는 화면 2~3개를 고른다. 로딩, 오류, 빈 목록, 임시 안내 화면은 피한다. UI에 원래 존재하는 결함은 조용히 수정하지 말고 출처에 기록한다.
5. 데스크톱은 1440 × 900에서 DPR 2, 모바일은 390 × 844에서 DPR 3을 기본으로 한다. 원래 앱 비율이 다르면 그 비율을 보존하고 프리셋에 적는다. 실제 파일 크기를 확인한다.
6. 화면 내부를 다시 그리거나 AI로 보정하지 않는다. 원본 캡처 바깥의 배경, 프레임, 위치와 크롭만 템플릿에서 조절한다.

```sh
agent-browser --session thumbnail-example set viewport 1440 900 2
agent-browser --session thumbnail-example open https://your-own-preview.localhost
agent-browser --session thumbnail-example snapshot -i
# 실제 화면을 조작해 데이터를 채우고, 로딩이 끝난 것을 확인한 뒤 캡처
agent-browser --session thumbnail-example screenshot /absolute/path/to/projects/example/screens/dashboard.png
agent-browser --session thumbnail-example close
```

호랑처럼 dev-env를 쓰는 경우 새 전용 환경을 만들고, `dev-env status`가 출력한 주소를 사용한다. 작업이 끝나면 그 환경만 `dev-env down`으로 내린다. 남의 피처 환경이나 브라우저 세션을 재사용하지 않는다.

## 오늘 사용한 예외

- NABABA: 저장소가 없어 사용자가 지정한 기존 커버 전체를 패널 안에 넣었다. 화면 일부를 추정해서 복원하지 않았다.
- 다옴: 현재 남은 코드인 홈, 로그인, 프로필을 기준으로 했다. 포인트와 기부 완료 화면은 만들지 않았다.
- 글루드: 작성 폼, 생성 결과, 작성 목록을 함께 썼다. AI 응답은 데모이며 모델의 실제 실행 결과로 표현하지 않는다.
- 디미페이: 2024년 키오스크와 앱을 사용했다. 웹 데모의 얼굴 인식 결과는 익명 데이터이고 실제 카메라 인식 검증은 아니다.
- 밥.net: 아이콘은 사용자가 지정한 원래 일러스트 배경을 보존했다. 커버의 원본 UI 색상도 유지했다.

## 업로드 전 확인

- 커버가 정확히 1600 × 900인지 확인한다.
- 이름과 핵심 화면이 332px 갤러리에서도 식별되는지 본다. 대표 카드는 약 688px에서도 확인한다.
- 화면의 글꼴과 데이터가 모두 로드됐는지, 모서리나 크롭이 주요 기능을 가리지 않는지 본다.
- 원본 화면과 비교해 비율과 색, UI 문구가 유지됐는지 확인한다.
- Notion 업로드 후 실제 사이트에서 갤러리와 모달을 연다. 가능하면 저장된 파일을 다시 받아 원본 SHA256과 비교한다.
- 캡처 원본, 프리셋과 출처는 보존한다. 임시 SDK, 의존성, 서버와 에뮬레이터는 정리한다. 사용자 키나 인증 파일은 보존 자료에 넣지 않는다.
